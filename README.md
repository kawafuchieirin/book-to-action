# book-to-action

「読んで終わり」にしないための読書管理リポジトリ。

本を読むことではなく、**行動が変わること**と**自分の言葉で発信できること**をゴールにしています。
Obsidian でも VS Code でもそのまま開けます。

---

## フロー

```
   📚 読みたい           📖 読書中            🗂 読書ノート
01_want-to-read  →    02_reading     →      03_notes/<年>
  Issueで1冊1件登録      読みながらメモ         読了して保管
                                                  │
                          ┌───────────────────────┴───────────────────────┐
                          ↓                                               ↓
                  🏃 変える行動                                   ✍️ アウトプット
                   04_actions                                      05_outputs
                 1冊につき1つだけ                               人に話す / 書く / 投稿する
                          └───────────────────────┬───────────────────────┘
                                                  ↓
                                            🔁 振り返り
                                             06_reviews
                                      定着したか / 来月何を読むか
                                                  │
                                                  └──→ 01_want-to-read へ戻る
```

番号順に一方向に進みます。迷ったら「今どの番号にいるか」だけ見ればOKです。

## フォルダの役割

| フォルダ | 役割 | 中身 |
| --- | --- | --- |
| `01_want-to-read/` | 読みたい本をためる | `want-to-read.md`（Issueから自動生成される一覧） |
| `02_reading/` | いま読んでいる本 | 読書中のノート（読み終えたら 03 へ移動） |
| `03_notes/<年>/` | 読み終えた本の書庫 | 年ごとに読書ノートを保管 |
| `04_actions/` | 行動変容の一元管理 | `action-tracker.md`（実践中 / 定着 / やめた） |
| `05_outputs/` | 発信したもの | ブログ・SNS・社内共有の下書きと記録 |
| `06_reviews/` | 月次振り返り | `YYYY-MM.md` |
| `templates/` | 各種テンプレート | 読書ノート / アウトプット / 月次振り返り |
| `scripts/` | 作業を1コマンドにするスクリプト | `new-book.sh` など |
| `integrations/` | 外部サービス連携 | Kindle購入通知メール → Issue |

## 使い方

### 0. 準備

```bash
git clone <このリポジトリ> && cd book-to-action
chmod +x scripts/*.sh   # 必要な場合のみ
```

Obsidian で使う場合は、このフォルダを vault として開くだけです。

### 1. 気になった本をためる（GitHub Issue）

**読みたい本は1冊1Issueで登録します。** スマホのGitHubアプリからでも登録できるので、書店や人との会話の場で思い出した瞬間に入れられます。

→ [Issueを新規作成](../../issues/new?template=want-to-read.yml) → 「📚 読みたい本を登録」を選ぶ

| フォームの項目 | 内容 |
| --- | --- |
| タイトル | `📚 ` のあとに本のタイトル |
| ジャンル | **必須。** プルダウンから選ぶ。該当なしは「✏️ その他」→ 次の欄に自由入力 |
| いまの状態 | **必須。** 📋 読みたい / 💰 購入済み / 📚 積読 / 📖 読書中 |
| 購入リンク | 任意。Amazon・楽天・出版社ページなど |
| きっかけ・解決したいこと | **必須。** なぜ今この本が気になったか |
| 手に入れたいもの | **必須。** 読み終えたときに何ができるようになっていたいか |
| 登録したときの気持ち | 任意。いま感じていることをそのまま（焦り・悔しさ・好奇心など） |
| 優先度 | 🔥 今すぐ / 🌱 そのうち / 🧊 一応メモ → 選ぶとラベルが自動で付く |

**この3項目はそのまま読書ノートの「読む前に：なぜ読むのか」に入ります。** 手で書き写す必要はありません。
読み終えたあとに「手に入れたか / 気持ちはどう変わったか」で読み返して照合するので、
**登録時の気持ちを残しておくほど、読後に何が変わったかが分かります。**

ローカルの一覧を更新したいときは同期します（Obsidianやオフラインで見るため）。

```bash
./scripts/sync-want-to-read.sh
# → 01_want-to-read/want-to-read.md の表を、オープンなIssueから再生成
```

**Issueが正（single source of truth）で、`want-to-read.md` はその写しです。** md側を直接編集しても次の同期で上書きされます。

一覧に出るのは **まだ読んでいない本（📋 読みたい / 💰 購入済み / 📚 積読）** だけです。
`📖 読書中` になった本は `02_reading/` のノートが本体なので、一覧からは外れます。

購入リンクを入れておくと、一覧のタイトルがそのままリンクになります（`[タイトル](URL)`）。
買うときに本を探し直す手間がなくなり、読み始めたあとはノートの `url` に残るので、
アウトプットで本を紹介するときにも使えます。

### 1.5 状態を更新する（Issueのラベル）

本の状態はIssueのラベルで管理します。**買った・積んだ・読み始めた・読了・やめた** が、Issue一覧でそのまま見えます。

| ラベル | 意味 | いつ付くか |
| --- | --- | --- |
| `📋 読みたい` | まだ買っていない | 登録時（初期値） |
| `💰 購入済み` | 買ったが読んでいない | **手でラベルを変更** |
| `📚 積読` | 買って放置している | **手でラベルを変更** |
| `📖 読書中` | 読んでいる | `new-book.sh --issue` が自動で付ける |
| `✅ 読了` | 読み終えた（Issueはclose） | `finish-book.sh` が自動で付ける |
| `🛑 辞めた` | やめた（Issueはclose） | `drop-book.sh` が自動で付ける |

買ったときだけGitHubでラベルを `💰 購入済み` に変えてください。それ以外はスクリプトが自動で更新します。

**Issueは読了かやめたときまで開いたまま** です。つまり `is:open` のIssue一覧が「いま抱えている本」になります。

```
is:open label:"📚 積読"                   積んでいる本を棚卸しする
is:open label:"📖 読書中"                  いま読んでいる本
is:closed label:"🛑 辞めた"                やめた本と理由を振り返る
is:open label:"🔥 今すぐ" label:"📋 読みたい"  次に買う本を決める
```

### 1.6 いまの状況を1コマンドで見る

ラベルを手で数えなくても、Issueから集計した状況を1コマンドで確認できます。

```bash
./scripts/status.sh
```

```
📊 いまの状況（2026-10-12 時点）

  📖 読書中      1 冊
  💰 購入済み    1 冊
  📚 積読       13 冊
  📋 読みたい    3 冊
  ----------------------
  2026-10 の読了   2 冊 / やめた 0 冊

📖 いま読んでいる本
  #12   🔥 イシューからはじめよ

🔥 次に読む候補（今すぐ）
  #15   💰 世界で闘う エンジニア・アウトプット力を鍛える本
  #3    📋 ［作って学ぶ］ブラウザのしくみ

⚠️ 気になる点
  - 積読が13冊あります。読まないと決めた本は drop-book.sh <番号> "理由" で手放す
```

| 引数 | 表示 |
| --- | --- |
| なし | 冊数のサマリ＋読書中＋`🔥 今すぐ` の候補 |
| `--all` | 未読の本を状態ごとに全件表示（棚卸し用） |
| `YYYY-MM` | 読了・やめた冊数を数える月を指定（省略時は今月） |

**集計元はIssueだけ** なので、`sync-want-to-read.sh` を実行していなくても正しい数が出ます。
「気になる点」は[困ったときの目安](#困ったときの目安)に引っかかったときだけ出ます（読書中が3冊超 / 読書中が0冊 / 積読が10冊以上）。
状態ラベルとopen/closedが食い違うIssue（close後にラベルが古いまま、など）は、冊数を狂わせないよう集計から外して件数だけ報告します。

### 2. 読み始める

```bash
./scripts/new-book.sh --issue 1
# → Issue #1 からタイトル・ジャンル・きっかけを取り込んでノートを作り、Issueをcloseする

./scripts/new-book.sh "イシューからはじめよ" "安宅和人"
# → Issueを使わず手で作る場合
```

Issueから作ると「解決したいこと」が埋まった状態で始められます。
読みたい本リストから消す作業も、Issueのcloseで同時に終わります。

読む前に「なぜ読むのか」を5分で埋めます。読みながら、ページ番号付きでメモを足していきます。

### 3. 読み終える

```bash
./scripts/finish-book.sh 02_reading/イシューからはじめよ.md
# → status: done / finished を記入し、03_notes/2026/ へ移動（git mv）
```

そのあとノートに書くのはこの5つだけ。

1. 1文で言うと
2. 重要ポイント3つ
3. **手に入れたか / 気持ちはどう変わったか**（登録時に書いたものと照合する）
4. **変える行動を1つ**（→ `04_actions/action-tracker.md` に転記）
5. 人に話すなら（30秒）

### 3.5 途中でやめる

合わない本はやめていいです。**理由だけ残します。**

```bash
# 読書中の本をやめる（ノートを03_notesへ移し、理由を追記、Issueをclose）
./scripts/drop-book.sh "02_reading/本のタイトル.md" "期待していた内容と違った"

# 読む前にやめる（Issueだけで完結）
./scripts/drop-book.sh 3 "先に別の本を読むことにした"
```

理由は必須です。同じ理由で何度もやめていたら、本の選び方を変えるサインになります。

### 3.7 Kindleのハイライトを取り込む

Kindleで線を引きながら読めば、それをそのまま読書メモ表に流し込めます。

```bash
# まず中身を確認（書き込まない）
./scripts/import-highlights.sh "02_reading/本のタイトル.md" ~/Downloads/Notebook.html --dry-run

# 取り込む
./scripts/import-highlights.sh "02_reading/本のタイトル.md" ~/Downloads/Notebook.html
```

エクスポートの取り方は3つあります（いずれも公式機能）。

| 方法 | 手順 |
| --- | --- |
| ブラウザ | [read.amazon.co.jp/notebook](https://read.amazon.co.jp/notebook) で本を選び「エクスポート」 |
| アプリ | Kindleアプリの「ハイライトをエクスポート」でメール送信 |
| 端末 | KindleをUSB接続し `documents/My Clippings.txt` をコピー |

HTMLと `My Clippings.txt` の両方に対応しています。

- Kindleの**メモは「自分の反応」の列**に入ります（ハイライトに紐づけて配置）
- ページ番号がない本は `位置1203` のように位置番号が入ります
- **同じ引用は飛ばす**ので、読み進めながら何度でも実行できます

取り込んだあとに「自分の反応（→ だから何？）」を埋めてください。引用を集めただけでは行動は変わりません。

### 4. 行動を管理する

`04_actions/action-tracker.md` に全部の本の行動が集まります。
「実践中」が5つを超えたら、増やす前にどれかを「定着」か「やめた」へ動かします。

### 5. アウトプットする

```bash
./scripts/new-output.sh "イシューを立てるだけで会議が早く終わった"
# → 05_outputs/2026-10-11_イシューを立てるだけで会議が早く終わった.md
```

読書ノートの「人に話すなら（30秒）」をコピーして膨らませるのが一番早い書き出し方です。
公開したら、元の読書ノートの「アウトプット記録」にも1行足します。

### 6. 月末に振り返る

```bash
./scripts/new-review.sh          # 今月
./scripts/new-review.sh 2026-09  # 月を指定
# → 06_reviews/2026-10.md を作成し、今月の読了冊数を表示
```

## スクリプト一覧

| コマンド | やること |
| --- | --- |
| `./scripts/status.sh [--all] [YYYY-MM]` | Issueから冊数・読書中・次に読む候補を集計して表示 |
| `./scripts/sync-want-to-read.sh` | オープンなIssueから `want-to-read.md` の表を再生成 |
| `./scripts/new-book.sh --issue <番号>` | Issueからノートを作成し、Issueを `📖 読書中` にする |
| `./scripts/drop-book.sh <パス\|番号> "理由"` | やめた記録を残し、Issueを `🛑 辞めた` にしてclose |
| `./scripts/new-book.sh "タイトル" "ジャンル"` | テンプレートから読書中ノートを作成（Issueなし） |
| `./scripts/finish-book.sh <パス>` | `status: done` と `finished` を記入し `03_notes/<年>/` へ移動（git mv 優先）、Issueを `✅ 読了` にしてclose |
| `./scripts/new-output.sh "タイトル"` | アウトプット用ファイルを作成 |
| `./scripts/new-review.sh [YYYY-MM]` | 月次振り返りを作成し、その月の読了冊数を表示 |
| `./scripts/import-highlights.sh <ノート> <エクスポート> [--dry-run]` | Kindleのハイライトを読書メモ表に取り込む |

## GitHub側の仕組み

| ファイル | 役割 |
| --- | --- |
| `.github/ISSUE_TEMPLATE/want-to-read.yml` | 読みたい本の登録フォーム |
| `.github/workflows/label-from-form.yml` | フォームで選んだ優先度とジャンルをラベルに反映する |

ラベルは4種類です。状態ラベルは常に1つだけ付いている状態がスクリプトによって保たれます。

| 種類 | ラベル |
| --- | --- |
| 分類 | `want-to-read` |
| 状態 | `📋 読みたい` / `💰 購入済み` / `📚 積読` / `📖 読書中` / `✅ 読了` / `🛑 辞めた` |
| 優先度 | `🔥 今すぐ` / `🌱 そのうち` / `🧊 一応メモ` |
| ジャンル | `💻 技術・エンジニアリング` / `☁️ インフラ・クラウド` / `📊 ビジネス・マネジメント` / `🧠 思考法・問題解決` / `🎨 デザイン・UX` / `🔬 教養・サイエンス` / `📕 小説・エッセイ` / `✏️ その他` |

ラベルになっているので、Issue一覧で `label:"🔥 今すぐ" label:"💻 技術・エンジニアリング"` のように絞り込めます。

**状態ラベルはフォームでは「初期値」を決めるだけ** で、以降はラベルが正です。
Issueの本文を編集しても `📖 読書中` が `📋 読みたい` に巻き戻らないよう、
状態の反映はIssue作成時（`opened`）のみに限定しています。

**ジャンルを増やしたいとき** は2箇所を直します。

1. `.github/ISSUE_TEMPLATE/want-to-read.yml` の `options` に追加
2. `.github/workflows/label-from-form.yml` の `GROUPS` のジャンル配列に、同じ文字列を追加
3. `gh label create "🍳 料理" --color C5DEF5 --description ジャンル` でラベルを作る

「✏️ その他」で登録したジャンルが増えてきたら、正式な選択肢に昇格させるのが運用しやすいです。

Issueを使わずローカルだけで運用したい場合は、`.github/` を削除して
`new-book.sh "タイトル" "ジャンル"` の形だけ使えば従来どおり動きます。

## Kindle連携

Kindleには**購入履歴や読書進捗を取得する公式APIがありません**。
そのため、公式に取り出せるデータだけを使って2つの連携を用意しています。

| 連携 | 使うもの | できること |
| --- | --- | --- |
| ハイライト取り込み | Kindleのエクスポート機能 | 読書メモ表が自動で埋まる |
| 購入の自動検知 | Amazonの注文確認メール | Issueが自動で `💰 購入済み` になる |

購入の自動検知は [integrations/gmail-to-github/](integrations/gmail-to-github/) にGoogle Apps Scriptとして
用意しています（サーバー不要・無料）。メール本文の商品ページURLからASINを取り出し、
同じASINを含むIssueを突き合わせます。**登録していない本を買った場合はIssueが自動で作られる**ので、
買ったのに登録を忘れた本が積読のまま消えません。

非公式に Kindle の内部APIを叩くライブラリも存在しますが、規約リスクがあり壊れやすいため使っていません。

## 続けるための最小限のルール

この3つだけ守れば回ります。

1. **行動は1冊につき1つだけ。**
   5個決めると0個になります。いちばん効きそうな1つに絞る。

2. **アウトプットは雑でいい。**
   完璧な記事より、140字の投稿や雑談のほうが続きます。「人に話した」も立派なアウトプット。

3. **途中でやめてもいい。**
   合わない本は `status: dropped` にして次へ。続かなかった行動は「やめた」に理由を書いて移す。
   やめた記録は失敗ではなく、自分の傾向を知るデータです。

### 困ったときの目安

| 状態 | やること |
| --- | --- |
| 読書中の本が3冊を超えた | 1冊に絞る。残りは `dropped` か `01_want-to-read` に戻す |
| ノートが書けない | 「1文で言うと」だけ書いて閉じる。それだけで十分 |
| アウトプットが出てこない | 人に30秒で話す。それをそのまま文字にする |
| 行動が続かない | 行動が大きすぎる。「いつ・どこで」をもっと具体的にする |
