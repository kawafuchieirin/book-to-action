# book-to-action

「読んで終わり」にしないための読書管理リポジトリ。

本を読むことではなく、**行動が変わること**と**自分の言葉で発信できること**をゴールにしています。
Obsidian でも VS Code でもそのまま開けます。

---

## フロー

```
   📚 読みたい           📖 読書中            🗂 読書ノート
01_want-to-read  →    02_reading     →      03_notes/<年>
  Issueで1冊1件登録      読みながらメモ         読了して保管
                                                  │
                          ┌───────────────────────┴───────────────────────┐
                          ↓                                               ↓
                  🏃 変える行動                                   ✍️ アウトプット
                   04_actions                                      05_outputs
                 1冊につき1つだけ                               人に話す / 書く / 投稿する
                          └───────────────────────┬───────────────────────┘
                                                  ↓
                                            🔁 振り返り
                                             06_reviews
                                      定着したか / 来月何を読むか
                                                  │
                                                  └──→ 01_want-to-read へ戻る
```

番号順に一方向に進みます。迷ったら「今どの番号にいるか」だけ見ればOKです。

---

## フォルダの役割

| フォルダ | 役割 | 中身 |
| --- | --- | --- |
| `01_want-to-read/` | 読みたい本をためる | `want-to-read.md`（Issueから自動生成される一覧） |
| `02_reading/` | いま読んでいる本 | 読書中のノート（読み終えたら 03 へ移動） |
| `03_notes/<年>/` | 読み終えた本の書庫 | 年ごとに読書ノートを保管 |
| `04_actions/` | 行動変容の一元管理 | `action-tracker.md`（実践中 / 定着 / やめた） |
| `05_outputs/` | 発信したもの | ブログ・SNS・社内共有の下書きと記録 |
| `06_reviews/` | 月次振り返り | `YYYY-MM.md` |
| `templates/` | 各種テンプレート | 読書ノート / アウトプット / 月次振り返り |
| `scripts/` | 作業を1コマンドにするスクリプト | `new-book.sh` など |

## 使い方

### 0. 準備

```bash
git clone <このリポジトリ> && cd book-to-action
chmod +x scripts/*.sh   # 必要な場合のみ
```

Obsidian で使う場合は、このフォルダを vault として開くだけです。

### 1. 気になった本をためる（GitHub Issue）

**読みたい本は1冊1Issueで登録します。** スマホのGitHubアプリからでも登録できるので、書店や人との会話の場で思い出した瞬間に入れられます。

→ [Issueを新規作成](../../issues/new?template=want-to-read.yml) → 「📚 読みたい本を登録」を選ぶ

| フォームの項目 | 内容 |
| --- | --- |
| タイトル | `📚 ` のあとに本のタイトル |
| 著者 | 任意 |
| 購入リンク | 任意。Amazon・楽天・出版社ページなど |
| きっかけ・解決したいこと | **必須。** なぜ今この本が気になったか |
| 手に入れたいもの | **必須。** 読み終えたときに何ができるようになっていたいか |
| 登録したときの気持ち | 任意。いま感じていることをそのまま（焦り・悔しさ・好奇心など） |
| 優先度 | 🔥 今すぐ / 🌱 そのうち / 🧊 一応メモ → 選ぶとラベルが自動で付く |

**この3項目はそのまま読書ノートの「読む前に：なぜ読むのか」に入ります。** 手で書き写す必要はありません。
読み終えたあとに「手に入れたか / 気持ちはどう変わったか」で読み返して照合するので、
**登録時の気持ちを残しておくほど、読後に何が変わったかが分かります。**

ローカルの一覧を更新したいときは同期します（Obsidianやオフラインで見るため）。

```bash
./scripts/sync-want-to-read.sh
# → 01_want-to-read/want-to-read.md の表を、オープンなIssueから再生成
```

**Issueが正（single source of truth）で、`want-to-read.md` はその写しです。** md側を直接編集しても次の同期で上書きされます。

購入リンクを入れておくと、一覧のタイトルがそのままリンクになります（`[タイトル](URL)`）。
買うときに本を探し直す手間がなくなり、読み始めたあとはノートの `url` に残るので、
アウトプットで本を紹介するときにも使えます。

### 2. 読み始める

```bash
./scripts/new-book.sh --issue 1
# → Issue #1 からタイトル・著者・きっかけを取り込んでノートを作り、Issueをcloseする

./scripts/new-book.sh "イシューからはじめよ" "安宅和人"
# → Issueを使わず手で作る場合
```

Issueから作ると「解決したいこと」が埋まった状態で始められます。
読みたい本リストから消す作業も、Issueのcloseで同時に終わります。

読む前に「なぜ読むのか」を5分で埋めます。読みながら、ページ番号付きでメモを足していきます。

### 3. 読み終える

```bash
./scripts/finish-book.sh 02_reading/イシューからはじめよ.md
# → status: done / finished を記入し、03_notes/2026/ へ移動（git mv）
```

そのあとノートに書くのはこの5つだけ。

1. 1文で言うと
2. 重要ポイント3つ
3. **手に入れたか / 気持ちはどう変わったか**（登録時に書いたものと照合する）
4. **変える行動を1つ**（→ `04_actions/action-tracker.md` に転記）
5. 人に話すなら（30秒）

### 4. 行動を管理する

`04_actions/action-tracker.md` に全部の本の行動が集まります。
「実践中」が5つを超えたら、増やす前にどれかを「定着」か「やめた」へ動かします。

### 5. アウトプットする

```bash
./scripts/new-output.sh "イシューを立てるだけで会議が早く終わった"
# → 05_outputs/2026-10-11_イシューを立てるだけで会議が早く終わった.md
```

読書ノートの「人に話すなら（30秒）」をコピーして膨らませるのが一番早い書き出し方です。
公開したら、元の読書ノートの「アウトプット記録」にも1行足します。

### 6. 月末に振り返る

```bash
./scripts/new-review.sh          # 今月
./scripts/new-review.sh 2026-09  # 月を指定
# → 06_reviews/2026-10.md を作成し、今月の読了冊数を表示
```

## スクリプト一覧

| コマンド | やること |
| --- | --- |
| `./scripts/sync-want-to-read.sh` | オープンなIssueから `want-to-read.md` の表を再生成 |
| `./scripts/new-book.sh --issue <番号>` | Issueからノートを作成し、そのIssueをclose |
| `./scripts/new-book.sh "タイトル" "著者"` | テンプレートから読書中ノートを作成（Issueなし） |
| `./scripts/finish-book.sh <パス>` | `status: done` と `finished` を記入し `03_notes/<年>/` へ移動（git mv 優先）、次の作業を表示 |
| `./scripts/new-output.sh "タイトル"` | アウトプット用ファイルを作成 |
| `./scripts/new-review.sh [YYYY-MM]` | 月次振り返りを作成し、その月の読了冊数を表示 |

## GitHub側の仕組み

| ファイル | 役割 |
| --- | --- |
| `.github/ISSUE_TEMPLATE/want-to-read.yml` | 読みたい本の登録フォーム |
| `.github/workflows/label-priority.yml` | フォームで選んだ優先度をラベルに反映する |

ラベルは `want-to-read` / `🔥 今すぐ` / `🌱 そのうち` / `🧊 一応メモ` の4つです。
優先度がラベルになっているので、Issue一覧で `label:"🔥 今すぐ"` で絞り込めます。

Issueを使わずローカルだけで運用したい場合は、`.github/` を削除して
`new-book.sh "タイトル" "著者"` の形だけ使えば従来どおり動きます。

## 続けるための最小限のルール

この3つだけ守れば回ります。

1. **行動は1冊につき1つだけ。**
   5個決めると0個になります。いちばん効きそうな1つに絞る。

2. **アウトプットは雑でいい。**
   完璧な記事より、140字の投稿や雑談のほうが続きます。「人に話した」も立派なアウトプット。

3. **途中でやめてもいい。**
   合わない本は `status: dropped` にして次へ。続かなかった行動は「やめた」に理由を書いて移す。
   やめた記録は失敗ではなく、自分の傾向を知るデータです。

### 困ったときの目安

| 状態 | やること |
| --- | --- |
| 読書中の本が3冊を超えた | 1冊に絞る。残りは `dropped` か `01_want-to-read` に戻す |
| ノートが書けない | 「1文で言うと」だけ書いて閉じる。それだけで十分 |
| アウトプットが出てこない | 人に30秒で話す。それをそのまま文字にする |
| 行動が続かない | 行動が大きすぎる。「いつ・どこで」をもっと具体的にする |
